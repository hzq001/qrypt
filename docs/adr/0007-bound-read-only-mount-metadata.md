# 挂载只读元数据查询使用协作式总超时

2026-10-28 的本机记录显示：后台遍历百度盘时，两次目录预取各在约 15 秒后超时，一次远端列目录耗时约 19.85 秒；同一时段的 FUSE `Getattr` 共耗时 35.27 秒。进程和 FUSE-T helper 均未退出，挂载随后自行恢复。这个时序支持“远端请求停顿经元数据查询传递到本机 NFS 挂载”的判断，但没有捕获到系统弹窗的直接事件，因此不把弹窗触发阈值当作已验证的常量。

原先 `Getattr`、`Access`、`Opendir`、`Readdir` 直接使用挂载生命周期 context。一次查询等待在途预取后，还可能继续发起远端请求，单次 HTTP 超时无法限制整个查询。另一个放大因素是目录缓存从远端请求开始时计时：请求耗时超过 10 秒时，成功返回的目录已经过期，接下来的缺失文件查询立即重新请求目录。

决定：这四个只读回调在原有 context 上派生 **10 秒总预算**，覆盖预取等待、路径解析和远端请求；底层超时沿用现有的 `EIO` 错误映射，日志保留 `context deadline exceeded`。目录缓存的有效期从远端成功返回、准备提交时开始。

这个决定保留 [FUSE 会话生命周期 ADR](0004-fuse-session-death-ends-the-process.md) 的单次回复约束：不另起 goroutine 执行回调，不抢先返回，不伪造成功；回调仍同步等待文件系统实际返回。context 只请求底层取消，因此忽略取消的驱动仍可能超过预算。写入、上传、删除以及文件内容传输沿用原有 context。

同次排查还复现了缺失文件查询的本地放大：父目录清单仍有效时，查询 `.git` 等不存在的文件仍会解析父路径并投影完整目录；投影中的 `LocalChildren` 会复制全局条目缓存。决定直接使用未过期的父目录完整清单判断缺失，在同一视图读锁内再次检查该路径的本地条目，避免漏掉首次缓存未命中后提交的本地文件。预取是否需要调度只检查目录缓存的有效期，不触发列表投影。这不新增独立负缓存、不延长有效期；过期、失效和清单中存在该名称时继续原有解析流程，`Stat` 仍先检查待传文件。

## 影响与验证

- 超过预算的目录浏览会收到本次查询失败；网络恢复后下一次查询可以正常工作，不需要把一次远端停顿升级为重启整个挂载。合法但耗时超过预算的超大目录也可能失败，这是保持挂载元数据应答有界的取舍。
- 作为等待方超时不会取消由其他请求启动的共享预取；预取成功后仍可供下一次查询使用。
- `testing/synctest` 覆盖四个回调的停顿、恢复、较早父级截止时间、关闭、底层忽略取消时等待完成、长写入不受影响、共享预取和缓存完整有效期。
- 缺失查询回归覆盖有效清单不再解析父路径或投影目录、过期和失效后重新查询、清单含条目但条目缓存缺失、本地条目在首次查询后提交、待传文件和新建目录可见。内存假盘基准隔离远端延迟；10 万条无关缓存时，单次缺失查询中位数从约 24 毫秒、99 MB 临时分配降至约 1 微秒、288 字节。它只衡量缓存命中路径，不能用于推断云盘网络请求加速。
- 本机 FUSE-T 1.0.44 的实挂探测显示：失败的路径查找无论收到 `EIO` 还是 `ETIMEDOUT`，`stat(2)` 都可能得到 `ENOENT`。因此不新增 errno 翻译，并以 FUSE 回调日志判断失败原因；不能把客户端的“文件不存在”当作远端确实不存在的证据。这是旧版 NFS 桥的限制，协作式预算不改变该错误转换。
- FUSE-T 的 NFS 架构及可用后端见[官方说明](https://github.com/macos-fuse-t/fuse-t/wiki)。本修复不依赖修改 NFS 超时参数或切换后端。
